## 윈도우 NT 아키텍처

윈도우 NT 아키텍처는 크게 두 개의 메인 구성 요소로 설계되어 있다. 추상화 개념을 통해 상위 레벨과 하위 레벨의 구조에 영향을 받지 않고 서로 상호작용할 수 있도록 구성된다.

1. 유저 모드
   - 사용자 애플리케이션 코드 실행
   - 시스템 데이터에 제한된 접근만 허용되며 하드웨어에 직접 접근 불가
2. 커널 모드
   - 하드웨어 접근과 보호된 메모리 내에서 실행되고 있는 코드와 컴퓨터의 시스템 자원 모두에 접근

스케줄링, 메모리 관리, 하드웨어의 상호 작용 등의 역할을 수행하며, 리소스 자원의 낭비를 줄이기 위해 여러 부분으로 쪼개어 설계된 구조이다.

## 유저 모드

- 환경 서브 시스템
  - OS/2, WIN32, POSIX 등의 환경에 맞는 애플리케이션을 운용할 수 있도록 지원
- 필수 서브 시스템(Integral Subsystem)
  - 보안, 워크스테이션 서비스, 서버 서비스로 구성
  - 보안: 계정 관리 권한, 인증 관리 등
  - 워크스테이션 서비스: 컴퓨터가 네트워크로 접근을 허용
  - 서버 서비스: 컴퓨터가 네트워크 서비스를 제공

## 커널 모드

- Executive
  - 모든 사용자 모드 하위 시스템과 상호작용
  - I/O Manager: 시스템 입출력 제어, 응용 프로그램이 하드웨어와 바로 통신할 수 있는 통로 제공
  - Security Reference Monitor(SRM): 보안 필수 서브 시스템의 보안 규칙을 시행하기 위한 주요 권한을 모니터링
  - IPC Manager: 서버와 클라이언트 사이의 상호작용 담당
  - Virtual Memory Manager: 가상 메모리 관리
  - Process Manager: 프로세스 생성 및 삭제
  - PnP Manager: Plug & Play 기능 관리
  - Power Manager: 전원과 관련 이벤트 관리 수행
- 디스플레이 시스템
  - Window Manager: 윈도우의 화면을 그리는 역할 수행
  - GDI(Graphics Device Interface): 폰트 렌더링과 팔레트, 곡선, 직선 등의 라인을 그리는 작업 수행
- 마이크로 커널
  - 하드웨어와의 통신만을 제어하는 최소한의 커널
  - HAL과 Executive 사이에서 멀티프로세서 동기화, 충돌 관리, 예외 관리 등 역할 수행
  - OS 부팅 시 필요한 드라이버 초기화 등 역할 수행
- 커널 모드 드라이버
  - 하드웨어 장치와의 상호작용을 수행할 수 있도록 중간자 역할
  - 최상위, 중간, 하위 레벨 드라이버로 구성
- Hardware Abstraction Layer(HAL)
  - 물리적 하드웨어와 운영체제의 나머지 부분 사이에 위치
  - 하드웨어의 차이를 숨기고 커널이 실행되는 일관된 플랫폼을 제공
