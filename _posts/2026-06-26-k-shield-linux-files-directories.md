리눅스 파일 시스템은 파일과 디렉터리의 계층적 구조를 가지고 있다. 디렉터리, 일반 파일, 특수 파일로 구분된다.

UNIX로부터 유래된 리눅스의 모토인 "Everything is a file"로 인해 모든 것이 파일로 액세스된다.

- 일반 파일
- 디렉터리 파일
- 특수 파일
  - 블록 장치 파일
  - 캐릭터 장치 파일
  - 심볼릭 링크 파일 등

## 트리 구조

리눅스 파일 시스템은 파일과 디렉터리의 계층적 구조를 지니고 있으며, 보통 서로 연관된 파일들을 하나의 그룹으로 모으고 각 그룹을 고유의 디렉터리에 보관한다.

계층 구조의 기초에는 루트 디렉터리가 있으며, `/`로 나타낸다.

| 디렉터리 | 의미 |
| --- | --- |
| `/bin` | 리눅스가 가지고 있는 각종 기본 프로그램을 포함한다. 보통 명령어가 저장되어 있다. |
| `/boot` | 리눅스를 부팅할 때 관련된 중요한 파일들. 커널 이미지와 부팅 정보를 포함하고 있다. |
| `/dev` | 특수한 디바이스 파일을 포함한다. 또 다른 디바이스를 추가할 때 사용한다. |
| `/etc` | 시스템 관리자를 위해 필요한 파일을 담아 놓는다. 대표적인 파일이 `passwd`이다. |
| `/home` | 사용자들이 사용할 수 있는 독립 공간. 사용자들이 사용하는 홈 디렉터리가 모여 있는 공간. |
| `/lib` | 시스템 프로그래밍을 위한 각종 라이브러리 저장 공간 |
| `/proc` | 커널의 기능 제어를 위해 커널에 대한 정보를 담고 있는 가상 파일 시스템을 포함 |
| `/tmp` | 리눅스 시스템이 사용하는 임시 파일을 저장 |
| `/var` | 시스템이 현재 운영 중인 시스템 자료의 모든 변경사항을 저장하는 공간 |

## Inode number

리눅스에서 파일에 접근할 때 실제로 파일 이름이 아닌, 이름과 매핑되어 있는 숫자로 접근한다. 이 숫자가 Inode number이다.

파일에 접근하는 절차는 다음과 같다.

1. 사용자가 `File1.txt`(Inode number 631)에 접근을 요청
2. Inode Table에서 Inode number가 631인 Inode 631 열람
3. Inode 631 안에 있는 Data Block(Pointer)을 통해 내용 열람

## 링크 파일

링크 파일은 하나의 파일 또는 디렉터리를 다른 이름으로 연결하는 것이다. 하드 링크와 심볼릭 링크 두 가지가 있으며, 하드 링크는 Inode 블록과 직접 연결되는 케이스이고 심볼릭 링크는 간접 연결되는 케이스이다.

- 하드 링크: inode number를 직접적으로 가리키는 파일이다. 하드 링크가 존재하는 원본 파일을 지워도 하드 링크 파일이 존재할 경우 원본 데이터가 삭제되지 않는다. 원본 파일의 파일 이름을 제외한 모든 것을 공유하므로 원본 파일의 속성이 변경될 경우 링크 쪽도 변경된다.
- 심볼릭 링크: 별도의 inode number를 가리키고 있으며, 원본 파일의 포인터를 가지고 있는 파일이다. 하드 링크와 다르게 원본 파일이 지워질 경우 링크가 깨진다.
